# PRD: Easy Transfer — 서울역 실내 길찾기 (Frontend MVP)

## 목표
개찰구를 통과한 이후, GPS가 닿지 않고 상업지도 서비스가 다루지 않는 지하철 역사 내부(승강장·환승 구간)를 외국인 관광객이 스스로 찾아갈 수 있도록, 경로 전체를 하나씩 체크해 나가는 안내 화면을 제공한다.

## 문제
- 구글맵·네이버지도·카카오맵 모두 역 밖에서 역까지는 정확하지만, 개찰구 통과 이후 구간은 다루지 않는다. GPS가 지하에서 작동하지 않고, 매장이 없는 순수 대중교통 공간은 지도 회사 입장에서 사업성이 없어 아무도 채우지 않았다.
- 핵심 사용자는 한국어 소통이 어렵고 국내 지도 앱 사용이 익숙하지 않은 외국인 관광객이다. 역무원·행인에게 물어봐도 언어 장벽이 있다.

## 사용자
국내 지도 앱(네이버지도·카카오맵)에 익숙하지 않고 한국어 소통이 어려운 외국인 관광객. 구글맵에는 익숙하지만 한국 실내·도보 길찾기의 공백 때문에 전환 장벽을 겪는다.

## MVP 범위 (Phase 0)
- 대상: 서울역 1개 역 (`SEOUL_STATION_KTX_TO_AREX` 맵)
- **출발지·도착지 입력 방식**: 실제 `GET /api/v1/maps/{mapId}/places` 응답에서 장소를 선택한다. 출발지는 `selectableAsStart`, 도착지는 `selectableAsDestination`인 항목만 노출하며 선택한 안정적인 `placeId`가 실제 라우팅 요청에 들어간다(`docs/ADR.md` ADR-017).
- 프로필: `STANDARD` / `LUGGAGE` 2종만 노출(도착지 입력 화면에 토글로 배치). `WHEELCHAIR`는 노출 금지 — 현장 검증이 안 됐다는 게 계약의 명시적 사유다.
- UI 언어: **영문 단일**. 다국어 전환 UI는 이번 MVP 범위 밖이다(자세한 배경은 `docs/ADR.md` ADR-005).
- 화면 흐름(5개, 선형): **출발지 입력 → 도착지 입력 → 로딩(경로 연결) → 안내 체크리스트 → 도착**. 상세 레이아웃은 `docs/UI_GUIDE.md` 참조.
- 지도: 경로 좌표는 API가 정규화 값으로 내려주며(`imageX`/`imageY`, `geometry`) 프론트는 그것을 SVG로 그린다. 역이용안내도 이미지는 KTX·1호선·4호선 대합실 도면 1장이 들어와 경로 뒤에 깔린다. 공항철도 층별 도면은 아직 없어 환승 이후 항목은 배경 없이 표시된다. 좌표는 계약이 스스로 밝힌 demo 데이터라 실제 지형지물과 정확히 일치하지 않는다(`docs/ADR.md` ADR-016).
- 데이터: 실제 백엔드의 `GET /api/v1/maps/{mapId}/places`, `POST /api/v1/routes`를 사용한다. API 주소는 `EXPO_PUBLIC_API_BASE_URL`로 덮어쓸 수 있고 기본값은 Render 배포 주소 `https://newbiethon-2026.onrender.com`이다.

## 핵심 기능
1. **출발지 선택** — API 장소 목록에서 출발 가능한 장소를 하나 고른다. 목록 조회 실패 시 재시도할 수 있다.
2. **도착지 선택** — API 장소 목록에서 도착 가능한 장소를 하나 고른다. 앞 화면에서 선택한 출발지 요약과 이동 프로필(Standard/With luggage)을 함께 보여준다.
3. **로딩(경로 연결)** — 선택된 두 `placeId`와 profile로 실제 경로를 조회한다. "출발지 → 도착지"를 보여주며 연결 중임을 알리는 화면. 실패 시 원인별 에러 상태를 재사용한다.
4. **안내 체크리스트** — 경로 전체가 목록으로 펼쳐지고, 현재 항목 하나만 카드로 열려 지시문·도착 지점 설명·경로 지도·완료 버튼을 보여준다. 완료한 항목은 체크되어 접히고 남은 항목은 번호만 보인다(`docs/ADR.md` ADR-015).
5. **도착** — 도착 확인, 이동 요약(거리·소요시간), 다음 열차 정보, 재시작/오류 신고 진입점.

## 에러·엣지 케이스 요구사항 (UX)
길 안내 도구는 "잘 될 때"보다 "안 될 때" 신뢰가 갈린다. 아래 시나리오는 전부 화면 명세의 일부로 취급한다 — 구현 시 빠뜨리면 스코프 미완료로 간주한다. 상세 비주얼은 `docs/UI_GUIDE.md` "에러·엣지 상태" 절, 상태 모델은 `docs/ARCHITECTURE.md` "에러 모델" 절 참조.

### 입력 화면 (출발지·도착지)
| 시나리오 | 기대 동작 |
|---|---|
| 아직 장소를 선택하지 않음 | "Continue"/"Find my way" 버튼이 비활성 상태를 유지한다. |
| 장소 목록 조회 중 | 로딩 표시를 보여주고 진행 버튼을 비활성화한다. |
| 장소 목록 조회 실패 | 네트워크/서버 오류 안내와 Retry 버튼을 표시한다. |
| 도착지 화면에서 뒤로가기 | 출발지 화면으로 돌아가며 기존 출발지 선택 상태를 유지한다. |

### 로딩(경로 연결) 화면
| 시나리오 | 기대 동작 |
|---|---|
| 선택한 장소 사이에 경로가 없음 | `NOT_FOUND`로 처리하고 "Choose a different destination" 버튼으로 도착지 선택 화면에 돌아간다. |
| 경로 조회 실패(경로 없음/잘못된 요청/서버 오류) | 도착지 매칭은 됐지만 그 뒤 단계에서 실패한 경우로, 원인별 문구는 위 "데이터 로딩 실패" 표와 동일하게 구분한다. |
| 요청이 8초 이상 걸림 | 스피너만 계속 돌리지 않는다 — "Still looking for a route…" 같은 중간 상태 문구로 멈춘 게 아님을 알린다. |
| 로딩 화면 진입 직후 곧바로 성공 | 로딩 화면이 깜빡이듯 스쳐 지나가도 어색하지 않아야 한다 — 최소 노출 시간을 인위적으로 늘리지 않는다(빠른 성공은 좋은 성공이다). |

### 경로 데이터 자체의 엣지 케이스
| 시나리오 | 기대 동작 |
|---|---|
| 체크리스트 항목이 0개 (출발지=도착지 등) | 안내 화면에 진입하는 즉시 감지해 도착 화면으로 리다이렉트한다. v1.2는 이 경우도 200으로 내려주므로 응답이 아니라 **펼친 결과**를 봐야 한다. **크래시를 유발할 수 있는 조건이므로 반드시 이 화면 진입 시점에 가드한다.** |
| 항목이 1개뿐인 아주 짧은 경로 | 체크리스트에 카드 하나만 떠도 어색하지 않아야 한다. 첫 항목이자 마지막 항목이므로 버튼 라벨은 곧바로 "I've arrived"가 된다. |
| 항목이 매우 많음 (예: 15개 이상) | 목록이 길어져도 현재 항목이 화면 밖에 있으면 안 된다 — 항목이 바뀔 때마다 현재 카드 위치로 자동 스크롤한다. |
| 해당 지도 이미지가 번들에 없음 (공항철도 도면 등) | 중립 패널 위에 경로 형태만 그린다. 지시문과 도착 지점 설명만으로 안내가 성립해야 한다(지도는 보조 수단 원칙). |
| `instruction`/노드 `description`이 비정상적으로 긴 문자열 | 어떤 화면 폭에서도(아이폰 SE 375px 포함) 하단 버튼이 화면 밖으로 밀려나지 않는다 — 스크롤 가능한 콘텐츠 영역과 항상 화면에 고정된 버튼 영역을 분리한다. |

### 사용자 행동 관련
| 시나리오 | 기대 동작 |
|---|---|
| 안내 도중 스와이프/하드웨어 뒤로가기로 이탈 시도 | 아직 아무 항목도 체크하지 않았으면 바로 나가되, 하나라도 체크한 뒤에는 "Leave this guide? Your progress won't be saved." 확인 다이얼로그를 띄운다. 실수로 안내를 잃는 상황을 막는다. |
| 안내 중 앱이 백그라운드로 전환 후 복귀 | 체크한 항목 수는 화면 컴포넌트 상태로 유지되므로 짧은 백그라운드 전환에서는 그대로 복원된다. 앱이 완전히 종료되었다가 재시작되는 경우까지는 보장하지 않는다(MVP 범위 밖 — 영속 저장소 없음). |
| 네트워크가 느려 로딩 화면에 오래 머무는 동안 재요청 남발 | 로딩 화면에는 재시도 버튼이 에러 상태에서만 나타난다 — 로딩 중에는 사용자가 추가 요청을 트리거할 방법이 없다. |
| 도착 화면에서 "Plan another transfer" | 스택을 전부 비우고 출발지 입력 화면으로 돌아간다(그 사이 화면들로는 뒤로가기 되지 않아야 함 — 끝난 안내는 스택에 남기지 않는다). |

### 접근성·기기 다양성
| 시나리오 | 기대 동작 |
|---|---|
| OS 모션 감소 설정 켜짐 | 경로선의 대시 흐름 애니메이션을 정지한다. |
| 스크린리더 사용 | 현재 항목이 바뀔 때마다 새 지시문이 자동으로 안내된다(`aria-live` 동급). 에러 문구도 포커스가 이동해 읽힌다. |
| 소프트 키보드가 화면을 가림 | 출발지·도착지 입력 화면은 키보드가 올라와도 입력 필드와 Continue 버튼이 가려지지 않는다(`KeyboardAvoidingView`). |
| 초소형 화면(iPhone SE, 375×667) ~ 태블릿 | 세로 스크롤은 허용하되 가로 스크롤은 어떤 화면에서도 발생하지 않는다. 지도 패널은 카드 폭에 맞춰 늘어나고 높이만 고정(140)이다. |
| 화면 회전 | MVP는 세로 고정이다(`app.json` orientation: portrait) — 가로 모드 대응은 범위 밖이며, 회전 자체가 발생하지 않는다. |

## MVP 제외 사항
- 다국어 UI(한/영/일/중) 전환 — 별도 데스크톱 스펙 문서에만 존재하며 이번 모바일 MVP 범위 밖.
- 서울역 외 다른 역, 역간 환승 경로.
- `WHEELCHAIR` 프로필 노출.
- 장소 자유 검색·자동완성·오타 교정·퍼지 매칭 — 현재는 API가 반환한 장소 선택 목록만 지원한다.
- 실시간 혼잡도·열차 지연 등 `FacilityDataStatus: LIVE` 연동 — 현재 그래프는 `STATIC`만 내려준다.
- 백엔드/인프라 작업 — 이 문서와 이번 작업 범위는 `frontend/`에 한정한다.

## 디자인
- 매체: React Native(Expo) 네이티브 앱, iOS/Android.
- 기준 목업: Claude Design 핸드오프의 `Easy Transfer App.dc.html` (390×844 모바일 플로우). 장소 선택과 로딩 화면은 기존 토큰·타이포·컴포넌트 스타일을 재사용한다(`docs/UI_GUIDE.md` 참조).
- 톤: 실용적인 내비게이션 도구. 장식적 그라디언트·글로우 없음, 핵심 정보(이동수단·거리·층)를 큰 글자로 우선 노출.
- 안내 화면 방향은 5개 시안 검토 후 **체크리스트(시안 E)** 로 확정했다(`docs/ADR.md` ADR-015).
